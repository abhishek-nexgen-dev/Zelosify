## Key implementation decisions

- Public jobs list only `OPEN` roles. Recruiting endpoints scope tenant admins/recruiters to their tenant and hiring managers to their assigned openings in that tenant.
- `Opening.requiredSkills` is now an explicit PostgreSQL `TEXT[]` field with an additive migration. Job create/edit persists it and deterministic skill matching reads this value rather than guessing skills from prose. An empty list currently produces skill match `1.0`.
- Candidate and vendor uploads use short-lived backend-generated signed PUT URLs, tenant/user/opening-scoped keys, exact content-type headers, metadata and initial signature checks, and 10 MiB per-file limits. Vendor batches are capped at 20 and saved in one database transaction after storage verification.
- Candidate application resumes support PDF, DOC, and DOCX at up to 10 MiB; vendor profile ingestion retains its existing PDF/PPTX support. PDF is parsed in a memory-limited worker, DOCX reads bounded document XML, and DOC uses `catdoc` with a 5-second timeout and temporary-file cleanup. Install `catdoc` on backend hosts for DOC support.
- Candidate applications now accept one `multipart/form-data` request at `POST /jobs/:id/apply`; candidate identity comes from authentication and the backend generates the scoped storage key. The signed-upload and JSON `s3Key` paths remain available for older clients.
- Recommendation score/confidence continue to be persisted in their existing fields and scales. Validated extracted features are additionally stored in `resumeAnalysis`, with a separate 0–100 `atsScore` and factor breakdown. Reviewer APIs expose them to recruiters and hiring managers; the UI labels them as decision support and keeps human shortlist/reject actions.
- Recruiter provisioning has no default password and requires a temporary password of at least 12 characters; Keycloak identity creation failure does not fall back to a fake local identity.
- Public registration now accepts candidate details only; role and tenant are server controlled. Registration requires an explicitly configured `DEFAULT_TENANT_ID`, and Keycloak role assignment failure prevents registration from succeeding.
- The API documentation audit found that `IT_VENDOR` was required by vendor routes but missing from the Prisma `Role` enum. Added `IT_VENDOR` and an additive migration, plus a vendor authorization regression test.
- Recruiter provisioning no longer accepts a shared fallback password; the request schema requires a temporary password of at least 12 characters.
- Demo credentials, fabricated client-side auth tokens, role switching, and fake OAuth callback success were removed. Logout clears the app cookies with matching development/production cookie settings.
- Manager candidate review now reports opening-detail loading/errors with retry, makes the recommendation count's current-page scope explicit, and retains paginated/virtualized results.
- `.env.example` now reflects PDF/PPTX support and the 10 MiB upload cap. `setup.md` explains how to configure the seeded tenant for self-registration.
- `api.doc.md` now includes the complete mounted-route index and detailed request/response/error examples. Root/backend/frontend READMEs, architecture/specification, checklist, implementation plan, product specification and setup guide were reconciled with the current paths and behavior.
